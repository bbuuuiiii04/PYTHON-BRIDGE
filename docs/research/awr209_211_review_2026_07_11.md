## VERDICT: PASS-with-required-fixes

The identity-safety mandate that drove this whole round — the red-team's finding
that beatgrid-alone matching flips songs under cross-analysis drift — is
**structurally satisfied**: the fingerprint path is now exact-only, and every
looser match is gated behind an independent tag lever. I verified the export.pdb
parser and its tag-matcher **on the real MINK stick + real master.db** and they
land on exactly the right content for real tracks. Path confinement and
corrupt-file crash-safety are solid under fuzzing. What holds it off a clean PASS:
the sidecar's phrase handoff has **no executed, no-mocked-seams proof** (the same
AWR-206/207 lesson I made a required fix on last round), a Task-2 spec deviation,
and one exception-taxonomy gap in the hand-rolled pdb parser. None are FAIL-level;
the tonight-critical path (AWR-209 pdb lever) is the well-verified part.

Plain-language: **the dangerous part — could a foreign stick light up as the wrong
song? — is provably closed, and I confirmed the pdb reader works on your real
stick. The unproven part is the foreign-laptop sidecar actually delivering phrase
end-to-end, which is staged (R3) and blocked on the AWR-210 exporter existing.**

  `_read_runtime_anlz_data` → assert non-empty `drop_beat_indices`). Genuinely
  blocked until AWR-210 emits a real sidecar — but AWR-211 must not be called
  "phrase works" without it. **[required, deferred-until-AWR-210]**
- **R2 — Reconcile `imported-not-analyzed`.** Spec Task 2 says resolve to **None**
  with the actionable reason; the code logs the reason then chains to
  `_sidecar_lookup` (filepath_resolver.py:857-859, 865-867). Benign on the
  operator's laptop (no sidecar → None) and arguably better on a foreign laptop,
  but it deviates silently and emits two reasons. Either return None per spec, or
  amend the spec to document the sidecar-chaining. **[required, small]**
- **R3 — Close the pdb parser exception taxonomy.** `_device_sql_string` indexes
  `data[offset]` / slices with unbounded file-derived offsets (filepath_resolver.py:302-315),

  backstopped by outer catch-alls (no crash — verified), but it mislabels the
  outcome as "sidecar-only mode." Add `IndexError` to those tuples or bounds-check
  the offset before indexing. **[required, trivial]**

## Surface-by-surface

### Surface 2 — Task-0 rule: is a beatgrid-alone loose match reachable? (the core mandate)

**[confirmed] No. The fingerprint path is now exact-only, and every looser match
requires an independent tag lever.**

- `_beatgrids_match` was rewritten to `len(usb) == len(local) and
  _beatgrid_fingerprint(usb) == _beatgrid_fingerprint(local)` (filepath_resolver.py:262)
  — the ±10 ms first-beat / ±10 ms sampled / ±1-count tolerance from AWR-207 is
  **removed**. `_unique_usb_twin` uses it, so the DB twin path resolves only on a
  bit-exact grid (mirror-class).
- The DB pdb lever (filepath_resolver.py:826-873) requires `device_track` (pdb tags)
  **and** `_usb_pdb_candidates` (title+artist+duration) **and** `_relaxed_usb_twin_match`
  (BPM+duration) before it resolves — the relaxed grid check only runs after tags
  independently agree.
- The sidecar path (`_select_sidecar_record`, filepath_resolver.py:549-590): exact
  fingerprint match (mirror-class) OR, on `device_track is None`, returns None with
  `usb-crossanalysis-unconfirmed` (line 563). Loose sidecar matches require the
  index's tags.

I could not construct a non-exact grid that resolves without tags through any path.
**[confirmed]** the red-team's flip mechanism is now impossible: an 11-20 ms
cross-analysis shift never produces a bit-exact fingerprint, so it can't match at
all (falls to tags or None). `test_cross_analysis_collision_cannot_flip_identity_without_tags`
(usb_twin) and `test_cross_analysis_collision_needs_tags` (sidecar) pin exactly this.

**[assumed→reasoned, Finding F4, LOW residual]** The exact-fingerprint path *can*
in principle match a different constant-tempo song whose grid is bit-identical
(same bpm+first-beat+count). On the mirror stick the co-present bit-exact true twin
forces a 2-match abstain (red-team measured 0/735); on a foreign stick a
drifted/re-analyzed grid cannot coincidentally land bit-exact on an unrelated
song's canonical grid. Residual is astronomically-unlikely, not zero — acceptable
and consistent with the mandate.

**[note] The red-team's specific 66 collision pairs / 121 flips are NOT loaded**
(the corpus is gitignored under `local/redteam_awr207/`, so it can't live in a CI
test). The tests encode the collision *class* synthetically. Since the strict
matcher makes the flip structurally impossible regardless of the specific pairs,
this is adequate — but it is a class pin, not a corpus replay.

### Surface 1 — Reachability through the REAL chain (pdb lever + sidecar)

**[confirmed] pdb parser is correct on real data.** I ran the real
`_parse_device_pdb_track` against the mounted `/Volumes/MINK/PIONEER/rekordbox/export.pdb`
(1,019,904 bytes, 735 USB ANLZ files) for six real tracks. It decoded sensible
title/artist/duration/bpm each time, e.g. `P000/0000013A` → "I Cannot (Extended
Mix)" / Anti Up / 239 s / 133 BPM; `P000/00009422` → "Losing It (Extended Mix)" /
FISHER / 400 s / 125 BPM. Cross-checked three against the real `master.db` via the
real `_usb_pdb_candidates`: **each matched exactly one DjmdContent** (127938342,
257624168, 113427509) with matching title/artist/duration — correct identity, no
ambiguity.

**[confirmed] the pdb lever's phrase flow is covered *compositionally*:** it ends in
`_payload_for_content(db, content, local_grid, local_anlz_path=...)`
(filepath_resolver.py:871-873) — the same function my AWR-207 e2e already proved
yields real `drop_beat_indices` from `local_anlz_path` → `read_anlz_drops`. Parser
→ correct content is verified on real data; content → phrase is verified by
`test_awr207_usb_phrase_e2e` (still green under the strict matcher).

**[unknown, Finding F1] the sidecar phrase flow is NOT proven end-to-end.** See R1.
Its `_payload_for_sidecar` points `local_anlz_path` into a sidecar-copied ANLZ
(filepath_resolver.py:594-641), but no test parses a real one; correctness depends
on AWR-210's copied ANLZ carrying PSSI, untestable here.

**[ceiling] the pdb *lever* (twin-miss → pdb → resolve) can't be exercised on MINK**
because MINK is a mirror stick — the exact-fingerprint twin always hits first, so
the pdb branch never engages there. Its end-to-end engagement is validated only by
mocked control-flow tests + the real parser check; a real cross-analysis foreign
stick is the operator gate (spec Part E acknowledges this).

### Surface 3 — Red-team collision regressions actually pinned?

**[confirmed] the class is pinned and the mechanism is closed.** `_unique_usb_twin`
returns `(None, 0)` for an 11 ms-shifted foreign grid against two colliders
(usb_twin test). `_select_sidecar_record` returns `usb-crossanalysis-unconfirmed`

(sidecar test:93-128). My real-data run adds live corroboration: real tracks
resolve to exactly-1 content, no false hits. Caveat per Surface 2 note: class pin,
not corpus replay.

### Surface 4 — Sidecar path confinement + corrupt-index crash-safety

**[confirmed] confinement is airtight.** `_sidecar_path` (filepath_resolver.py:457-463)
`.resolve()` + `.relative_to(root)`. I fuzzed it: absolute `/etc/passwd` → None,
`../../etc/passwd` → None, **symlink escape** (link inside sidecar → outside dir) →
None, legit relative → confined. Every `anlz_relpath`/`v4_relpath` is validated at
load (filepath_resolver.py:428-451) AND re-checked in `_payload_for_sidecar`.
`test_missing_and_path_escape_are_silent_misses` pins the `..` case.

**[confirmed] corrupt/malicious pdb never crashes.** I fed the real parser empty,
16-byte, header-garbage, half-truncated, one-page-truncated, and random-1 MB
inputs: every one returned None or raised `struct.error`/`ValueError` — all inside
the callers' caught set. Schema-gated, type-validated JSON index (schema_version
mismatch → None + log; malformed record → None).

**[Finding F3, LOW] one taxonomy gap:** a *crafted* (not merely corrupt) pdb with a
valid page structure but an out-of-range string offset can raise IndexError from
`_device_sql_string`, which the narrow except tuples miss. No crash (outer
catch-all backstops), but it degrades with the wrong reason. → R3.

### Surface 5 — Local-first precedence (sidecar NEVER when local hits)

**[confirmed].** The UUID match returns immediately (the AWR-207 path,
unchanged) before any device/sidecar logic. For non-device paths the function
ends `return _sidecar_lookup(...) if device_export else None` (filepath_resolver.py:889)
→ None, so local paths never touch the sidecar. `test_local_uuid_hit_never_consults_sidecar`
patches `_sidecar_lookup` and asserts `assert_not_called()`. The sidecar is reached
only on device-export + twin-miss + pdb-miss, i.e. strictly after the local DB is
exhausted — matching the charter order master.db → sidecar → miss.

**[note, F2]** `imported-not-analyzed` chains to the sidecar rather than returning
None (see R2).

### Surface 6 — Scripted ssid parity via both new sources

**[confirmed for the pdb lever]:** it resolves via `_payload_for_content` →
`_read_soundswitch_id(content.FolderPath)` — byte-identical to local/AWR-207. My
real-data check proves the pdb lever lands on the correct content, so its FolderPath
(hence ssid) is right.

**[assumed for the sidecar]:** ssid comes from `record["soundswitch_id"]`
(filepath_resolver.py:633); `test_sidecar_payload_carries...` asserts it equals the
`_payload_for_content` ssid. The field flows; real parity depends on AWR-210 writing
the correct ssid into the index — an AWR-210+211 integration gate, untested here (F5).

### Surface 7 — Two-USB discovery correctness

**[confirmed].** `_discover_sidecar_index` scans all `/Volumes` mounts (sorted,
casefold), returns the first with a valid `RBSS BRIDGE USB/lighting_sidecar/index.json`,
caches per session (filepath_resolver.py:513-524). The pdb lever reads the
**guest** stick's `export.pdb` (from the load's ANLZ path, filepath_resolver.py:410)
while the sidecar reads **his** stick's index (from discovery) — correctly
independent for the two-USB case. `test_discovers_his_sidecar_beside_guest_stick_and_caches_it`
pins guest+his discovery and the session cache.

**[note] if two sticks both carry a sidecar**, discovery picks the alphabetically
-first mount (deterministic but arbitrary). Unlikely for the operator; worth a log
if it ever matters.

### state_manager sidecar-v4 seam

**[confirmed clean].** `_read_runtime_anlz_data` takes `sidecar_v4` and prefers it
over the spectral cache (`v4 = sidecar_v4`; the extract path is gated `elif
audio_filepath`, state_manager.py:243-269). `_start_anlz_worker` threads it through;
`_on_filepath_resolved` passes `payload["sidecar_v4"]` only when present
(state_manager.py:2573-2574). Local loads (no `sidecar_v4` key) are unaffected —
`worker_kwargs` only gains the key when non-None. `test_runtime_prefers_payload_v4_over_local_cache`
asserts `get_cached_v4` is not called and the `source=sidecar-v4` log fires. One
minor behavior change: the outer spectral guard dropped its `audio_filepath`
requirement so `beatgrid_times_ms` now populates even with an empty audio path — no
downstream harm found (the spectral block repopulates it anyway).
