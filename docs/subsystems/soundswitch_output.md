# SoundSwitch Output

Status:
- implementation: alpha
- software-tested: partial
- hardware-validated: no repo evidence
- compatibility: my local SoundSwitch setup only

Purpose:
- Send VirtualDJ-shaped OS2L messages and helper fanout to SoundSwitch.

Offline project export:
- `soundswitch_pack_models.py`, `soundswitch_project_decoder.py`, `soundswitch_pack.py`, `soundswitch_pack_verifier.py`, and `tools/export_soundswitch_pack.py` implement frozen source models, strict read-only decode, deterministic export of a repo-local canonical pack, and independent verification for the pinned SoundSwitch 2.10.3 canonical project UUID/RAVE profile. Live export performs a dynamic saved-project rescan and reconciles Venue, scripted, Autoloop, MIDI, artifact, manifest, and active-cue-union counts from the generated pack. The old closure snapshot counts remain proof-only via explicit strict verification. Software tests cover the dynamic default, proof-only snapshot gate, 32 Static Looks, seven-class F-3 crosswalk, and F9 mutation rejection.
- The independent verifier now rejects the runtime-loader metadata failures before publication: duplicate active learned-controller events, duplicate active Static Override slot ownership, invalid device-agnostic Static Override targets, project-target bridge scenes that are not pack selections, missing Autoloop targets, and an empty bridge scene crosswalk. The clean canonical pack still verifies and loads; these checks only fail closed on packs the loader would refuse.
- `import_report.json` records report-only operator visibility for reserved MIDI event reclassifications and supported mapped scripted files that are inactive because their source file is missing. It remains sanitized and does not add source paths to runtime-visible metadata.
- Parity lane evidence is now fed by capture-derived registries under `tests/fixtures/soundswitch/`: scripted U0 witnesses, Autoloop U0 phase samples, and a Static Look fallback record from the attempted-but-unavailable static windows in `parity_20260701T185231Z`. `tools/export_soundswitch_pack.py` recomputes each surface's registry at export time from the committed capture fixtures (`tests/fixtures/soundswitch/parity_oracle/*_reduced.json`) against the pack actually being exported, and recompiles/re-stages once if the fresh registries differ from the committed snapshot; a venue-cue ADDITION (which changes `SoundSwitchVenues.bin`'s sha and every `venue_source_sha256` pin) self-heals instead of permanently stranding every witnessed document in `unverified_parity` until someone manually reruns `tools/ssfmt/update_parity_registry.py`. A loop/document whose render no longer matches its own capture rows is pinned to a FAIL registry entry and fails closed to `unverified_parity` rather than silently falling back to generalization; a loop/document with no capture rows still gets no registry entry and may still qualify for `algorithm_generalized`. A capture fixture that is present but whose registry builder raises fails the export loudly rather than publishing with degraded evidence. Static Looks pass the C6 non-generic assertion and export as `algorithm_generalized`. Fresh export reports active lanes `algorithm_generalized: 69`, `oracle_proven: 14`, `unverified_parity: 0`, so trusted publication is software-gated green.
- The immutable pack loader/player, MIDI-input adapter, output-backend abstraction, Enttec frame sender, validated default-off config, startup bundle, atomic runtime controller, status block, and runtime commands are implemented and software-tested components.
- T7b loads config and builds the player/controller/sender; T7c wires the sole per-tick frame driver into `StateManager`; T7e adds validate-first reload/backend/enable commands and sanitized status. All remain default-off and hardware-unvalidated.
- **RW-1 Export from SS** (`tools/export_soundswitch_pack.py`, `scripts/bridge_menubar.py`): one explicit menubar click runs a full read-only decode/compile/verify in a subprocess and publishes to repo-local ignored `local/soundswitch/rbss_canonical_pack`. The replace path uses macOS `renamex_np(RENAME_SWAP)` when available; its move-aside fallback retains a recoverable backup, restores the old pack if the second rename fails, and deterministically recovers the newest real-directory orphan backup on the next publish. Non-directory backup entries are removed and can never become canonical. A cross-process lock and in-process click guard serialize publishers. The tracked example config names the absolute local checkout path for this canonical pack while remaining `enabled=false`, `dry_run=true`, and `output_backend=none`; `load_pack()` expands `~` if an operator config still uses it.
- After disk publication, the menubar distinguishes saved from live. If the bridge is stopped or pack output is disabled, it sends no command and reports saved-not-live. A stale or unconfirmed bridge snapshot also sends no reload and reports saved — live reload not confirmed. If the live pack already serves the identical exported content, the menubar reports it live without re-sending a reload. Only fresh, enabled, changed-content state appends the existing `set_soundswitch_pack reload` command and accepts a fresh `soundswitch_pack.pack_sha12` match as the reload acknowledgement. It never sends enable/backend, starts or restarts the bridge, or opens a device.
- The export action is clickable **Export from Soundswitch** when the saved source may differ, disabled **Exported** only with positive proof that the pack exists, the exact source-content fingerprint matches, and the stored generator commit is valid and matches the current commit when Git can determine it; it is disabled **Exporting…** while publication runs. Detection performs content hashing and commit lookup on a background worker; only its cheap stat-signature gate runs on the AppKit thread. Each successful canonical publish best-effort writes a hashes-and-commit-only source-fingerprint sidecar beside the pack, never inside it. The sidecar ignores stable retained-opaque backup/media/preset paths, but keeps `recordable/*.dat` in the fingerprint because those files are dynamically parseable and can later carry learned-MIDI/control-state content; detection applies the same filter to older sidecars. A missing, corrupt, unreadable, or otherwise uncertain source-fingerprint sidecar state remains clickable. The required binding sidecar is different: publish stages it before the canonical swap, fails closed with `sidecar_failed` before swap if it cannot be produced, and preserves the prior pack.
- **T7c pack driver** (`StateManager._drive_pack_output`, run once per tick via the `_push_tick` wrapper): the **sole caller of `PackOutputBackend.submit_frame`** — do not add another. The executor's `backend.trigger()` is scene-SELECTION only and never emits DMX, so the two never collide. The driver READS `DeckState`; `StateManager` remains the only writer. The driver hard-suppresses pack output to software ZERO while the OS2L/SoundSwitch connection provider reports connected; the menubar auto-switch remains the release/disable path. Automatic scripted base ZEROs on stop/stale/error/track-change/discontinuity via `LaserPackPlayer.clear_selection()`, so a held manual Static Override stands alone while idle (SoundSwitch parity); static still loses to blackout/emergency/pack-disabled/shutdown. The pure player skips non-primary fixture-group attributes before applying scripted or static rows, matching the pack compiler's primary fixture policy. Native Autoloop base output is implemented in software: the fresh laser scene edge, or the executor's latched active Autoloop scene when no fresh edge is present, resolves through `LoadedPack.autoloop_bindings`, latches across no-edge ticks, computes phase with `AUTOLOOP_TICKS_PER_BEAT = 600` and `phase_offset_beats`, calls `LaserPackPlayer.select_autoloop()`, then uses the same render/submit path. Missing bindings/files/layout fail closed; authored all-zero Autoloops are valid dark looks. The old T7d gate no longer blocks it, but phase calibration/live runtime/hardware validation remain open.
- Scripted-track playback prefers verified pre-rendered boundary frames when every event carries one. Normal generated packs still require boundary frames to match cue replay; explicit `pre_render_status: oracle_rendered` is reserved for capture-derived literal scripted boundaries. The current callable GhidraMCP pass confirmed the reader/cache shape but did not find a footer/prefix/shared-byte remap or any single global key-offset fix. Scripted lane generalization now applies across the three supported loaded-layout variants only after a current U0 PASS witness exists and the target document resolves every positive reference into the current cue set; stale or unresolved cue references still fail closed as `unverified_parity`. Autoloop playback still uses event replay, but each cycle starts from zero before signed negative pre-roll/current-cycle events; segment-aware capture reduction promotes the PASS Autoloop samples and records non-PASS contiguous segments as divergence diagnostics instead of registry evidence; when a segment passes, any other non-PASS sibling segments for that same Autoloop are also ledgered (as `sibling_segment_failed_oracle`) and copied into the registry's `divergence` field alongside the promoted PASS rows, so a promoted Autoloop's known-bad capture segments stay visible rather than silently dropped. Static Looks use the separate generic-attribute overlay path; the current capture did not produce accepted held-static U0 windows, so their parity lane is generalized from the existing static byte/assertion evidence rather than direct per-slot U0 rows.
- **Art-Net truth-check gate** (`RBSS_ARTNET_TRUTH_CHECK=1` plus valid `RBSS_ARTNET_UNIVERSE`, normally `1`): implemented as a temporary validation-only U1 shadow-output path. Startup can build a verified pack runtime with `PackOutputBackend(frame_sender=None)`, learned MIDI input, and an `ArtNetTruthSink` without opening Enttec or serial. While SoundSwitch/OS2L is connected, production pack output still submits software ZERO, but the same pack render decision is enqueued non-blockingly to U1 with sidecar metadata. `RBSS_ARTNET_UNIVERSE` by itself emits nothing; invalid truth-check env fails closed. The comparator requires fresh matching run IDs from both bridge status `truth_check.run_id` and the sidecar header, ordered nearest-neighbor U0/U1 byte matches within tolerance, strict sidecar frame index/sequence/hash agreement for every captured U1 packet, and coverage only from matched frame rows; an unterminated final sidecar JSONL line is treated as pending but never as evidence. In live streaming mode it finalizes only a settled prefix — deferring the newest frames and tolerating the sidecar leading received U1 (the sink writes each row before sending its packet) — so a leading/denser stream stays pending instead of failing, while a real byte mismatch on a settled frame still fails. Failed native Autoloop statuses do not satisfy Autoloop coverage, scripted IDs are compared in normalized lowercase/no-brace form, Autoloop phase buckets use each loop's `cycle_ticks`, and scripted timeline events require observed elapsed progression from a near-start row. `tools/artnet_compare.py --self-check` exercises synthetic parser/matcher/sidecar/timing/coverage cases without sockets or hardware.
- If an ordinary exception escapes the 200 Hz drain/tick/snapshot iteration, `StateManager._run` submits at most one direct pack ZERO frame, logs a bounded error counter, preserves the normal tick throttle, skips only that instant, and continues. `_push_tick()` inner failures keep their existing ZERO-before-reraise path, so `_run()` logs/throttles without sending a duplicate ZERO. This darkens only the pack lane for the bad tick; OS2L/laser-MIDI and LED/Govee lanes are separate and may hold their last output until their next successful decision.
- **T7e runtime control** (`soundswitch_pack_runtime.py`, `soundswitch_pack_controller.py`): the live pack runtime is one immutable `PackRuntime` bundle published to `StateManager` by a single atomic assignment (`set_pack_runtime`), so the push loop reads a consistent snapshot per tick. The `set_soundswitch_pack` runtime command (reload/backend/enable) is validate-first on the command thread via `SoundSwitchPackController`: no implicit hot-enable; stop-before-start on the shared Enttec serial port with an explicit `frame_sender.zero_and_stop()` on the OLD sender (NoneBackend.submit_frame is a no-op, so the bundle swap alone does not darken the rig); no partial swap; pack failure → disabled/none, never MIDI; runtime `backend=midi` deferred. Sanitized `soundswitch_pack` status + sanitized command errors (no paths/ports/aliases/devices/UUIDs/raw messages).
- **RW-5 copied operational status:** `PackRuntime.sanitized_status()` exposes immutable bundle facts without calling a backend/provider. `StateManager` publishes a fresh bounded dict from the already-rendered frame decision before the existing submission, and `get_pack_status()` returns only a copy. The booleans preserve simultaneous truths such as degraded controller input with a continuing scripted base; the display enum uses `disabled`, `blackout`, `input_degraded`, `static_held`, `scripted_active`, native Autoloop states (`rendering_active`, `empty_dark_look`, `missing_binding`, `missing_autoloop_file`, `unsupported_layout`, `soundswitch_present_native_suppressed`), `autoloop_phase_blocked`, or `software_zero_frame`. The nested `native_autoloop` block carries role, scene, note, SoundSwitch display name, target identity, anchor beat, phase tick, reason, and diagnostic. `frame_count` counts attempted normal software frames. None of these fields proves serial delivery, Enttec acceptance, or fixture darkness.
- The menubar reuses one row for the copied pack state and export progress/result. A stale status file renders `Lighting: no status yet`; the export/reload action still uses only the existing conservative reload command and never enables output or changes backend.
- **Menubar auto-switch** (`scripts/bridge_menubar.py`): separate from the export/reload action, `_auto_set_soundswitch_pack()` (`:883`, called from `:813`) flips pack output by SoundSwitch connection state by enqueueing `{"cmd":"set_soundswitch_pack","action":"enable","enabled":<bool>}`. A failed auto-enable with fresh disconnected status and `pack_start_failed` gets one bounded retry, not per-refresh spam. There is **no implicit hot-enable**: enabling still requires a real `output_backend="pack"` + `dry_run=false` + Enttec port, so a dry-run/none/no-config bundle stays disabled. There is no manual pack on/off menu button.
- **Static Override Press/Toggle interaction mode**: the bridge honors the SoundSwitch-saved interaction policy instead of operator config. `soundswitch_project_decoder.py:855-888` decodes the saved `PushButton+0xc1` byte (`mode_raw==1` ⇒ `toggle`, else `press`); `PackMidiBinding`/`PackStaticLook` carry `interaction_mode ∈ {press, toggle}` (`soundswitch_pack_models.py:250,260`, `soundswitch_pack_loader.py:53,283-296`); and `SoundSwitchMidiInputAdapter` latches toggle slots on note-on and ignores note-off for toggles while keeping press/momentary behavior (`soundswitch_midi_input.py:220-252`). `SoundSwitchMidiInputGroup` derives controller inputs from active `static_look` bindings; `midi_input_aliases` are optional overrides, missing/ambiguous controller ports degrade manual Static Looks while pack DMX continues, and blackout/output-bus bindings are not auto-opened as inputs. An unknown saved mode fails closed to momentary. The canonical pack is published to and loaded from the repo-local ignored path `local/soundswitch/rbss_canonical_pack`.
- A blackout-mask note is a real hold: it stays held until note-off/velocity-zero or an unambiguous adapter clear such as port loss, worker death, stop, panic, reload, or `mark_unavailable`. There is no short age-based self-release while the controller port remains alive.
- **Confirmed active gaps:** sender/serial delivery health is not present in RW-5; native Autoloop DMX has software tests but no live/runtime or hardware run in repo evidence; and no real hardware run exists. The reviewed procedure and evidence template are `docs/validation/soundswitch_hardware_validation_procedure.md` and `docs/validation/soundswitch_hardware_runs/TEMPLATE.md`.
- Live SoundSwitch OS2L behavior and all other bridge outputs remain unchanged; no hardware validation was performed.
